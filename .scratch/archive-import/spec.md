# 压缩包拖入 — 设计方案

Status: ready-for-agent
日期：2026-09-24
Feature slug: `archive-import`
范围：在已落地的批量导入之上，把 zip / 7z / rar 拖入「输入 BLF」变成与文件夹等价的来源。
产物落位复用已定义的镜像输出树，本 spec 不重开那条规则。

用户确认（2026-09-24）：

1. 解压目录默认落在压缩包同级的 `<压缩包主名>/`，并保留。
2. 每次导入都强制重新解压：目标目录已存在则整目录删除后再解压。

---

## Problem Statement

上游发来的测试数据经常是一个 zip、7z 或 rar，而不是已经解开的文件夹。
批量导入已经能拖文件夹和散 `.blf`，但压缩包拖进「输入 BLF」会被整行拒绝。
用户仍要自己解开、再把解开的文件夹拖进去，多一步，也容易把产物和原始包放乱。

## Solution

把压缩包当成「先解开、再按文件夹读」的来源：

1. 拖入 zip / 7z / rar（大小写不敏感）到「输入 BLF」，工具把它解压到与压缩包同级的 `<压缩包主名>/`。
2. 每次都强制重新解压：同名解压目录已存在就整目录删掉再解，保证内容与当前压缩包一致。
3. 解压完成后按文件夹来源递归找出全部 `.blf`，候选清单、共用一套配置、批量转换全部沿用今天的批次流程。
4. 产物落在与压缩包同级的镜像输出树 `<压缩包主名>_t/`。解压树与产物树并排，压缩包本身不动。

单文件 `.blf` 与文件夹拖入的行为保持不变。「浏览…」仍只选单个 `.blf`。

## User Stories

### 拖入与识别

1. 作为测试工程师，我想把一个 zip 直接拖进「输入 BLF」，以便不必先手动解压再拖文件夹。
2. 作为测试工程师，我想把一个 rar（rar4 与 rar5）直接拖进「输入 BLF」，以便上游发来的 rar 包同样能一次导入。
3. 作为测试工程师，我想把一个 7z 直接拖进「输入 BLF」，以便 7z 包不必换工具解开。
4. 作为测试工程师，我想让压缩包扩展名大小写不敏感（`.ZIP` / `.Rar` / `.7Z`），以便从资源管理器拖出的文件不会因为大小写被拒绝。
5. 作为测试工程师，我想一次拖入多个压缩包，以便把几个包汇总成同一张候选清单。
6. 作为测试工程师，我想在同一次拖入里混合压缩包、文件夹和散 `.blf`，以便分散的数据一次进批次。
7. 作为测试工程师，我想在拖入的条目里没有压缩包、文件夹或 `.blf` 时整行拒绝，以便拖错类型时有明确的拒绝反馈，而不是静默无反应。
8. 作为测试工程师，我想在解析、扫描或转换进行中拖入被拒绝，以便忙碌态与今天一致，不会出现「接受了却没反应」。
9. 作为测试工程师，我想继续用「浏览…」只选单个 `.blf`，以便单文件点选手感不变；压缩包入口只走拖拽。

### 解压位置与强制重解压

10. 作为测试工程师，我想让解压结果落在与压缩包同级的 `<压缩包主名>/`，以便原始包、解开的数据和产物三样并排，我能打开解开的目录核对 BLF。
11. 作为测试工程师，我想每次拖入都按当前压缩包重新解压，以便包被替换或更新后不会读到上一次解开的旧文件。
12. 作为测试工程师，我想在同名解压目录已经存在时先整目录删除再解压，以便目录里不会残留上一次多出来的文件。
13. 作为测试工程师，我想让这次删除只碰解压目录，压缩包文件本身和已有的镜像输出树 `<压缩包主名>_t/` 都保留，以便重导不会毁掉已经转好的产物，也不会删掉原始包。
14. 作为测试工程师，我想在解压目录名与一个我自己的同名文件夹撞车时仍按上述规则替换该目录，以便规则没有例外；我知道这个目录归这次解压所有。
15. 作为测试工程师，我想在同一次拖入里既有压缩包、又有它的解压目录时只按压缩包处理，以便不会先扫一个即将被删掉的目录。
16. 作为测试工程师，我想在压缩包所在目录不可写时得到明确失败提示，以便我知道要换一个可写位置再拖，而不是文件被悄悄解到别处。

### 解压之后如何变成批次

17. 作为测试工程师，我想让解开后的目录按文件夹来源递归找出全部 `.blf`（含各级子目录），以便包内多层目录一次拿全。
18. 作为测试工程师，我想让包内 `.blf` 扩展名大小写不敏感，以便 `.BLF` / `.Blf` 不会被漏掉。
19. 作为测试工程师，我想在候选清单里看到每个文件在包内的相对路径和大小，以便区分同名文件并判断哪个是大文件。
20. 作为测试工程师，我想让候选顺序确定（同样的包每次顺序一致），以便勾选可以靠肌肉记忆。
21. 作为测试工程师，我想在包里只有一个 `.blf` 时不弹勾选列表，直接进入，以便单文件包不被多余的一步打断。
22. 作为测试工程师，我想在包里有多个 `.blf` 时弹出勾选列表（全选、逐个勾、已选计数），以便只转我关心的那几个。
23. 作为测试工程师，我想在实际参与批量超过 1 个文件时看到共用一套配置的提示，只勾选 1 个时不看到，以便与今天的批次规则一致。
24. 作为测试工程师，我想让平台、项目、CAN-DBC 绑定对这批文件只配一次，通道集合取并集，以便压缩包来源和文件夹来源是同一套批次。
25. 作为测试工程师，我想在「输入 BLF」行看到来源名和文件数，完整路径进 tooltip，以便确认当前批次来自哪个包。

### 产物落位

26. 作为测试工程师，我想让压缩包来源的产物落在与压缩包同级的镜像输出树 `<压缩包主名>_t/`，以便不必先解压再手工整理产物位置。
27. 作为测试工程师，我想让镜像树里只有树根带 `_t`、内层目录沿用包内原名、只有 MDF 文件名追加 `_t`，以便从产物路径能反推它在包里的位置。
28. 作为测试工程师，我想让镜像树只复刻通向至少一个 `.blf` 的目录，空目录和无关文件不进产物树，以便产物树干净。
29. 作为测试工程师，我想让包内根目录上直接躺着的 `.blf` 落成 `<压缩包主名>_t/<主名>_t.mdf`，以便规则没有例外。
30. 作为测试工程师，我想在混合拖入时让散 `.blf` 就地落位、文件夹走自己的镜像树、压缩包走自己的镜像树，以便三种来源互不影响。
31. 作为测试工程师，我想在只选 1 个文件时仍能手改输出路径且手改值优先，批量（> 1）时输出框只读，以便与今天的批次一致。

### 失败、取消与进度

32. 作为测试工程师，我想在包内一个 `.blf` 都没有时看到明确提示「未找到可导入的 .blf 文件」，以便知道拖错了包，而不是静默结束。
33. 作为测试工程师，我想在压缩包损坏或格式不受支持时看到解压失败原因，以便知道是包的问题而不是工具没反应。
34. 作为测试工程师，我想在压缩包已加密时看到「当前版本不支持加密压缩包」，以便不会卡在要密码的半截解压上。
35. 作为测试工程师，我想在磁盘空间不足时看到解压失败原因，以便我去清空间而不是得到一个半截目录。
36. 作为测试工程师，我想在解压或随后的目录遍历中途取消，以便拖错一个大包时能立刻停下。
37. 作为测试工程师，我想在取消或解压失败时清掉这次未完成的解压目录，以便不留下半截数据；取消前已经存在的镜像输出树不动。
38. 作为测试工程师，我想在遍历解开后的目录时，无权限或被占用的子目录被跳过并记日志，而不是整次导入失败，以便与文件夹来源同一政策。
39. 作为测试工程师，我想在解压阶段看到「正在解压」的不确定进度，解压完成后看到已发现的候选计数，以便大包解压时窗口不是假死。
40. 作为测试工程师，我想在解压进行中关闭窗口时被询问确认，以便不会误关丢掉这次导入。

### 安全与内容边界

41. 作为测试工程师，我想让压缩包里带 `../` 或绝对路径的条目无法写到解压目录之外，以便恶意包不能改我盘上的其他文件。
42. 作为测试工程师，我想让包内嵌套的压缩包不被继续解开，只收集这一层解开后的 `.blf`，以便不会无限递归，也不会把内层包误当成 BLF。
43. 作为测试工程师，我想让同一 `.blf` 被两条路径命中时只保留一份候选，以便不会转出两份一样的产物。

### 回归

44. 作为测试工程师，我想让直接拖入或浏览单个 `.blf` 的行为与今天逐字一致，以便日常单文件操作零回归。
45. 作为测试工程师，我想让拖入文件夹的镜像输出树、勾选、共用配置、批量转换、取消和无残留与今天一致，以便压缩包只是多了一种来源，不改批次本身。

## Implementation Decisions

**来源类型扩展，不新开一条输出规则**

压缩包是第三种拖入条目（与散 `.blf`、文件夹并列）。识别之后的候选、勾选、共用配置、批量转换全部走现有批次。镜像输出树的三条约束不变：只有树根带 `_t`、树在源的同级、只复刻通向至少一个 `.blf` 的目录。

**解压目录**

- 解压根 = 压缩包所在目录 / `<压缩包主名>`（去掉扩展名，大小写按文件名原样）。
- 例：`D:\drops\A02.zip` → 解压到 `D:\drops\A02\`，产物在 `D:\drops\A02_t\`。
- 主名含多个点时只去掉最后一个扩展名（`run.2026.zip` → `run.2026\`）。
- 解压根必须与压缩包同级。所在目录不可写（创建失败或删除失败）时整次该条目失败，向用户展示原因，不改解到其他盘或其他临时目录。改到别处会让镜像输出树的「同级」落点跟着跑偏。

**每次强制重新解压**

- 开始解压前，若解压根已存在，整目录删除后再解压。
- 不存在则直接创建并解压。
- 删除范围只有这个解压根。压缩包文件、镜像输出树 `<主名>_t/`、解压根以外的任何路径都不删。
- 解压根与用户自有的同名文件夹撞车时同样删除后重建。这是确认过的规则，不是缺陷。
- 同一次拖入中，若另一个条目的路径就是该解压根、或位于其内部，跳过该条目，只处理压缩包。避免扫一个马上会被删掉的目录。

**解开之后复用文件夹来源**

解压成功后，把解压根当作文件夹来源交给现有的文件夹候选逻辑。不另写一套输出路径计算。因此：

- 候选的 BLF 路径指向解压根内的文件，不指向压缩包内的虚路径。
- 相对显示名 = 该文件在解压根内的相对路径。
- 输出路径 = `<压缩包主名>_t/` 下的镜像路径。

输出路径仍在解析期一次算定。

**解压后端（沿用 2026-09-23 实测，不重新选型）**

| 格式 | 后端 |
|---|---|
| zip、rar（rar4 / rar5） | Windows 自带 `System32\tar.exe`（bsdtar / libarchive）。零额外二进制。 |
| 7z | py7zr。系统 tar 的 libarchive 未编 LZMA，不能用来解 7z。 |

不捆绑 7-Zip 或 WinRAR。目标平台是 Windows 冻结 exe。`tar.exe` 不存在时，zip/rar 条目失败并说明缺少系统解压组件。7z 不依赖 tar。

**路径穿越**

- zip/rar：依赖 bsdtar 默认拒绝 `../` 与盘符绝对路径（已实测）。
- 7z：解压前检查条目名，拒绝 `..`、盘符路径、以 `/` 或 `\` 开头的绝对路径；解压过程中若目标路径跳出解压根，中止并按失败清理。
- 穿越被拒绝时，该压缩包条目失败，不留下部分写出到解压根之外的文件。

**加密、嵌套、损坏**

- 加密包：检测到需要密码则失败，文案说明当前版本不支持加密压缩包。不弹密码框。
- 嵌套压缩包：只解一层。内层 zip/7z/rar 不当成 BLF，也不再解。
- 损坏或无法识别：失败并带上后端给出的原因，映射成用户能读的一句说明。

**取消与失败清理**

解压与随后的目录遍历都接入现有取消信号：取消抛出 ConversionCancelled，由界面按「已取消」处理，不按失败弹窗。

- 取消或解压失败：若本次已经创建或已经清空过解压根，删掉这个未完成的解压根。
- 强制重解压意味着取消前旧的解压根已经被删掉，取消后不恢复旧内容。
- 镜像输出树不在这次清理范围内（无残留管的是转换产物，不是解压目录；这里单独清理的是未完成的解压根）。
- 解压成功之后的转换失败 / 批次取消，仍只按现有无残留与批次取消语义处理产物，不回头删已完成的解压根。

**进度**

解析的进度分两段，仍由同一次解析上报，界面不自己解压：

1. 解压段：没有候选总数，界面用不确定进度，文案为正在解压（带来源名）。
2. 枚举段：沿用今天的「已发现候选数」计数（单调不减，无百分比）。

**界面保持薄**

- 拖拽判定增加压缩包扩展名。命中 0 个可导入项时整行拒绝。
- 单个散 `.blf` 仍走今天的单文件加载，不经解析。判定必须是「一个条目且是 `.blf`」，不能是「一个条目且是任意文件」——否则单个压缩包会被误送进单文件加载。
- 单个压缩包、多个条目、文件夹，都走现有的解析 worker。解析模块无 Qt。
- 「浏览…」不增加压缩包过滤，不增加多选或选文件夹。
- 不新增常驻控件。忙碌态锁定的控件列表不扩充。

**依赖与冻结**

- 新增 Python 依赖仅 py7zr，供 7z。zip/rar 无新依赖。
- 冻结打包带上 py7zr 的运行所需，不打包 tar.exe。体积裁剪只去掉确认用不到的部分，不以裁剪破坏 7z 解压。

## Testing Decisions

好测试只断言外部行为：给定压缩包路径（以及它旁边的文件系统），解析结果里的 BLF 路径、输出路径、相对显示名、大小，以及解压根是否被重建、失败时解压根是否还在。不锁定调用了 tar 还是 py7zr 的内部顺序，不穿透私有函数。

**接缝：一个，复用已有的来源解析**

最高接缝是现有的来源解析：输入路径集合，输出候选清单。压缩包的解压位置、强制重解压、镜像输出树、空包、取消、穿越失败，都从这个接缝看得见，不另开「解压模块」测试面。解压实现可以是解析内部的一件事；测试不导入它。

用例落在与现有来源解析测试同一风格（临时目录里放合成压缩包，直接调用解析，无 Qt）：

- zip / 7z / rar 各一份：包内多层 `.blf` → 解压根在压缩包同级 `<主名>/`，候选输出在 `<主名>_t/`，五条镜像约束逐条成立（同级、根带 `_t`、内层原名、文件名 `_t`、空目录与无关文件不产生候选）。
- 解压根已存在且里面有额外文件：再次解析后该额外文件消失，内容与当前包一致。
- 同级已有 `<主名>_t/` 里的文件：重解压后仍在。
- 压缩包文件本身：重解压后仍在。
- 同一次路径集合里同时有压缩包和它的解压根：只产出压缩包来源的候选。
- 混合散 `.blf` + 文件夹 + 压缩包：三种落位各算各的。
- 包内零个 `.blf`：空清单。
- 扩展名大小写：`.ZIP` 与包内 `.BLF` 都能进清单。
- 取消发生在解压之后的遍历中：抛取消信号，不留下半截解压根。
- 条目名含 `../` 的包：解析失败或该包被拒绝，解压根之外不出现被穿越出去的文件。
- 加密包：失败，且不留下半截解压根。
- 不可写的父目录：失败，不在其他位置冒出解压根。

合成包在测试里用标准库 zip 与 py7zr 创建。rar 若运行环境没有可用的 rar 写入器，则用一份提交在测试夹具里的最小 rar，或在缺少 tar 时跳过并注明；zip 与 7z 不得跳过。

**现有 GUI 拖拽接缝只加一条行为**

沿用窗口级拖拽事件注入，不断言解压过程：

- 拖入一个压缩包会进入解析，而不会走单个 `.blf` 的加载。
- 非 `.blf`、非目录、非压缩包的拖入仍整行拒绝。
- 解析被短路成「1 个候选」时不弹勾选列表；短路成多个候选时弹出。这验证接线，不重测解析本身。

**不新增的测试面**

- 不测 tar 命令行参数或 py7zr 的调用次数。
- 批量编排、对拍、共用配置文案已有测试，本功能不改它们的契约，不复制一遍。
- 单文件 `.blf` 的既有测试必须零改动通过。

先例：来源解析测试（镜像树五条约束、去重、取消、无权限跳过）；GUI 批量拖拽测试（事件注入、对话框短路）。

## Out of Scope

- 「浏览…」选择压缩包、多选或选文件夹。
- 加密包的密码输入与解密。
- 嵌套压缩包的递归解压。
- 单独的体积上限（字节数封顶）。磁盘写满按解压失败处理，不另设阈值。
- 解压到临时目录并在转换后删除。用户确认保留同级解压根。
- 解压根已存在时跳过解压、复用旧内容。用户确认每次强制重解压。
- 不可写位置改解到 AppData 或其他盘。不可写即失败。
- 批内并发、跨文件复用进程池、统一输出目录、批次持久化。
- 分发 7-Zip / WinRAR 或其他第三方解压二进制。
- 非 Windows 平台的 rar/zip 兜底。

## Further Notes

镜像输出树的压缩包落点已在领域词汇表和 `batch-import` 方案里定义，本方案只补「解压根在哪、如何重解压、失败如何收口」。实施时不要改散 `.blf` 与文件夹的落位。

`batch-import` 方案把压缩包列为范围外，并注明输出规则可直接复用。那份文档保持原样；本文件是压缩包阶段的规格。

强制重解压会删除同名解压目录里的全部内容，包括用户事后拷进去的文件。界面不必为此再弹一次确认——规则已定为每次重建。日志里记一句「已重新解压」即可，避免静默删目录时完全无迹可循。
