# 02 — rar 与 7z 走同一条来源

**What to build:** 测试工程师拖入 rar（rar4 或 rar5）或 7z 时，得到与 zip 相同的结果：强制解压到同级 `<压缩包主名>/`，候选进入现有批次，产物落在 `<压缩包主名>_t/`。扩展名大小写不敏感。

**Blocked by:** 01 — zip 拖入解压并进入批次

**Status:** ready-for-agent

- [ ] 拖入 `.rar` / `.RAR` 解压到同级 `<主名>/`，候选与镜像输出树规则与 zip 相同
- [ ] 拖入 `.7z` / `.7Z` 同样解压、同样落位
- [ ] 再次拖入同一 rar 或 7z 会删除解压根后重建，且不删除压缩包和已有 `<主名>_t/`
- [ ] rar 不引入新的解压二进制（走系统 tar）；7z 用 py7zr，冻结运行时能解 7z
- [ ] 系统缺少 tar 时，rar 条目失败并说明缺少解压组件，不静默丢弃
- [ ] 单个 rar 或 7z 走进解析，不走单个 `.blf` 加载；与文件夹、散 `.blf` 混合拖入时各按各的规则落位
