# 01 — zip 拖入解压并进入批次

**What to build:** 测试工程师把一个 zip 拖进「输入 BLF」，工具把它解压到与压缩包同级的 `<压缩包主名>/`，再按文件夹来源找出包内全部 `.blf`，进入现有批次（一个文件不弹勾选列表，多个文件弹勾选并共用一套配置）。产物落在同级镜像输出树 `<压缩包主名>_t/`。每次拖入都先删掉同名解压目录再解压。散 `.blf` 和文件夹拖入与今天一样。

**Blocked by:** None — 可立即开工

**Status:** ready-for-agent

- [ ] 拖入 zip（扩展名大小写不敏感）会解压到压缩包同级的 `<主名>/`，主名只去掉最后一个扩展名
- [ ] 解压根已存在时整目录删除后再解压；压缩包文件本身和已有的 `<主名>_t/` 保留
- [ ] 包内 `.blf`（含子目录、扩展名大小写不敏感）成为候选：相对显示名是包内相对路径，输出路径在 `<主名>_t/` 镜像树（根带 `_t`、内层目录原名、MDF 文件名带 `_t`、空目录与无关文件不进候选）
- [ ] 包内零个 `.blf` 时候选为空，界面给出「未找到可导入的 .blf 文件」
- [ ] 同一次拖入混合 zip、文件夹和散 `.blf` 时，三种来源各按各的规则落位
- [ ] 同一次拖入里同时有 zip 和它的解压目录时，只按 zip 处理
- [ ] 解压期间界面处于忙碌态并显示正在解压；解压完成后恢复已发现候选计数。单个 zip 不会走单个 `.blf` 的加载
- [ ] 非 zip、非目录、非 `.blf` 的拖入仍整行拒绝；「浏览…」仍只选单个 `.blf`
- [ ] 来源解析无 Qt，可脱离界面断言上述行为；既有单文件 `.blf` 与文件夹测试零改动通过
