# H2 对拍工具收口 — 设计 Spec

> 来源：2026-08-18 架构审查（[2026-08-18-architecture-review.md](./2026-08-18-architecture-review.md) 第 3 节 H1/H2、第 5 节候选 F）+ 逐项 grilling（用户逐轮确认，所有决策已 settle）。词汇表见 [CONTEXT.md](../../CONTEXT.md)：对拍、逐位一致、回退 oracle。

## Problem Statement

验收工具链中 7 个对拍脚本各自独立重写「加载两组 → 对齐 → 逐点比较」，没有任何一份是另一份的超集，能力散落三处；对拍 oracle（`compare_two_mdf`）的判定逻辑无法被 import，测试只能复制第三份实现（`_mdf_equal`），三份对拍语义已悄悄分叉（缺 t 轴、缺容差、多 equal_nan）。oracle 自身没有任何测试保护——oracle 出错则整条对拍链静默失真。另有 2 个变质残留脚本（docstring 声称对比两个文件、实际只读第一个参数或只打印不比较），2 处硬编码参考组索引（结构一变即静默错位）。

## Solution

把全部对拍判定收口为**单一深模块、两个公开入口**，pytest 与 CLI 穿过同一个 seam；保留两个验收入口文件名（自产对拍、CANoe 参考报告）为 thin adapter；删除全部冗余脚本。模块行为是现有各脚本判定的**超集**（独有能力全数并入），容差语义逐入口保持现有默认，不统一——「行为不变、结构变」。

## User Stories

1. 作为验收工程师，我想运行自产 vs 自产对拍命令，以便确认并行/串行输出逐位一致，命令在差异时以非零退出码退出并打印差异位置，从而脚本化验收。
2. 作为验收工程师，我想运行自产 vs CANoe 参考对比命令，以便确认转换输出与 CANoe 报告一致（组匹配、时间对齐、统计逐点），并获得 Markdown 报告。
3. 作为验收工程师，我想对拍判定覆盖文件头 10 个字段（含 author/department/project/subject/comment），以便捕获元数据漂移。
4. 作为验收工程师，我想对拍判定覆盖统计组的 t 轴与逐点数值（160 组 × 601 点、1e-9 容差），以便完成修复项 4 的验收。
5. 作为验收工程师，我想在参考文件结构变化（如统计组布局改变）时报错而不是静默错位，以便尽早发现参考布局漂移。
6. 作为验收工程师，我想关闭某些比较维度（如跳过统计组），以便定向调试特定差异。
7. 作为测试作者，我想直接从测试代码 import 对拍判定（而不是复制实现），以便消除第三份拷贝及其语义分叉。
8. 作为测试作者，我想用合成 MDF 构造已知相等/不等的对拍用例，以便在无样例数据的环境下验证判定正确性。
9. 作为维护者，我想删除 5 个冗余/变质脚本后剩余验收命令行为逐位不变，以便降低验收链的维护成本（21 → 约 6~7 个脚本）。
10. 作为维护者，我想对拍判定自身有黄金测试保护，以便 oracle 出错时不静默失真（H1 修复目标）。
11. 作为维护者，我想文本通道比较做字节归一化（尾随 \x00 剥离），以便枚举文本比较不因定宽填充误报。
12. 作为维护者，我想组序颠倒的自产对拍被判定为差异，同时 CANoe 参考对比按信号集合匹配而通过，以便两种对齐策略各按其契约工作。

## Implementation Decisions

### D1. 模块形状：单一深模块，两个公开入口

对拍判定收口为验收工具目录下的一个共享模块，两个公开函数，共享内部基础（文件加载、10 字段文件头比较、结构比较、字节归一化）。两个入口的契约（对齐策略、容差、统计语义）彼此独立，不共用参数矩阵。

- `compare_files_identical(ref_path, ours_path, *, dims=DEFAULT_DIMS) -> list[str]`
  自产 vs 自产：按**组序号**对齐，组序一致是硬性要求；逐通道 dtype + 精确逐位 + 每组 t 轴。
- `compare_files_reference(ref_path, ours_path, *, stats_ref_idx, dims=DEFAULT_DIMS) -> list[str]`
  自产 vs CANoe 参考：按**信号集合**匹配组（参考组序可变）；时间对齐容差对比；统计组 t 轴细查与逐点验收。`stats_ref_idx` 为**必填**参数（无默认值）——调用方必须显式声明参考统计布局，硬编码错位从静默变报错。

返回值：人类可读的差异描述行列表；**空列表 = 一致**。CLI 负责打印、退出码（0/非 0）、报告文件——报告不属于模块契约。

### D2. 维度系统：四个维度，默认全开

`dims` 为四维集合 `{header, structure, values, stats}`，两个入口默认全开；CLI 提供逐维关闭开关（用于定向调试）。各维度承载的独有能力（全部来自现有脚本，合并而非改写语义）：

- **header**：文件头 10 字段逐字段判定（version / start_time / abs_time / tz_offset / flags / author / department / project / subject / comment）。
- **structure**：组数、组名、通道序、unit、dtype、bit_resolution、CN 元数据三项（cn_data_type / cn_bit_count / cn_conversion，升级为判错而非记录）、组内信号序；统计组通道名差异汇总。
- **values**：逐点数值判定——文本走字节归一化后精确比较；整型精确；浮点按入口容差。
- **stats**：统计组判定——'1s' 组数、组内信号序、统计 t 轴细查、160 组 × 601 点逐点（整型精确、浮点 1e-9）。

### D3. 容差语义：参数化，每入口保留现有默认，不统一

模块暴露 `atol` / `rtol` 参数，CLI 可覆盖；默认值逐入口继承现有脚本语义：

- identical 入口：1e-12 **有效容差**（浮点差 ≤ 1e-12 视为一致，NaN 比较语义沿用现有实现）。
- reference 入口：`isclose(1e-6, rtol=1e-6, equal_nan=True)` 全量；统计逐点 1e-9；时间对齐窗口 1e-3 s。

统一容差会悄改验收判定、需要重新对拍一遍，明确排除。

### D4. CLI：两个 thin adapter，文件名不变

保留两个验收入口为薄壳（参数解析 → 调模块 → 打印 + 退出码）：

- **自产对拍**：用法与退出码契约不变（0 = 一致，非 0 = 差异）。
- **CANoe 参考报告**：CLI、Markdown 报告、终端 + 文件双写行为保留；新增必填的参考统计布局参数（替代硬编码），验收命令同步更新文档。

### D5. 删除与消重

- 删除 5 个脚本：2 个变质残留（声称对比但只读第一个参数 / 只打印不比较）、3 个独有能力已并入模块的脚本。
- 测试中的第三份对拍实现拷贝替换为 import 模块（两处断言改用同一入口），消除语义分叉。
- 删除不涉及任何生产代码（core/、gui/ 零改动）——不触碰性能前提与逐位一致对拍链。

### D6. 行为不变原则

模块的判定行为是现有各脚本的等价或超集。超集部分（reference 入口默认全开后新增的头部/统计 t 轴等维度）以一次真实数据对拍验证（原版脚本 vs 收口模块输出逐行一致）作为实证，不口头承诺。

## Testing Decisions

- **只测外部行为，不测实现细节**：所有测试穿过两个公开入口（唯一 seam），传入合成 MDF 文件路径，断言差异列表的内容与空性——不触碰模块内部结构。
- **被测模块**：共享对拍模块（经 identical / reference 两个入口）。
- **测试数据**：合成 MDF（asammdf 构造，无样例数据依赖——已知本环境样例数据缺失）。
- **用例清单**（tests 覆盖）：
  1. 相等对 → 空列表（两入口各一对）
  2. 单点改值 → 报出组/通道/索引
  3. 容差边界：浮点差 1e-11（identical 报）vs 1e-13（identical 过）
  4. 组序颠倒：identical 报、reference 按信号集合匹配通过
  5. 头部 10 字段逐一差异 → 报字段名
  6. 文本通道字节 \x00 归一化 → 通过
  7. 统计 t 轴：合成统计组 + 显式参考统计布局 → t 轴差报出
  8. 时间对齐窗口边界（1e-3 s 两侧）
- **先例**：现有 test_converter 的「只经公共接口 + asammdf 读回断言」模式；test_parallel_decode 的真实数据对拍断言（保留，改用共享入口）。
- **真实数据回归**：行为等价验证步骤——AHT 82MB 真实文件上，原版脚本与收口模块输出逐行一致 + pytest 全绿。
